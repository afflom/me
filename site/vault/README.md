# Vault

The owner's content, kept in their own browser. `vault.mjs` seals each value with
AES-GCM-256 and files it under a keyed content address (`k1:` + HMAC-SHA-256 of the
value). It decides nothing: every keep and every read is a question to the app's
verified guest, and the vault obeys the answer.

| Question | Facet keyword | Module | Answers |
| --- | --- | --- | --- |
| May this fact stay in the browser? | `boundary` | `PrismBoundary` | allow, hashonly, ask, deny |
| May the vault keep it? | `store` | `PrismVaultStore` | store, storehash, ask, refuse |
| May the vault give it back? | `restore` | `PrismVaultRestore` | restore, hashonly, refuse |

`routerDecide(dispatch)` turns the guest's `dispatch(line)` into those three
questions. An answer the vault does not expect is a refusal.

## Keys and storage

- One AES-GCM key and one HMAC key, generated by the browser as non-extractable
  CryptoKeys and kept in IndexedDB. No passphrase and no unlock step: an unlocked
  device is the owner. No script can read the key bytes.
- A passphrase is asked only to make or read an encrypted export (`PVX1`,
  PBKDF2-SHA-256 at 600 000 iterations, each entry bound to the header and its
  position). Import files every entry again through the Boundary and `store`,
  under the new browser's own keys.
- Object bytes go to OPFS (`<name>/objects/`), or to IndexedDB where OPFS cannot
  write. The index holds address, kind, size and time: no labels, no values.
- The seal's associated data binds format, kind and address, so a swapped or
  relabelled object fails to open and `restore` refuses it.
- If the key ring is lost, every read and keep is refused and nothing is deleted.

## API

```js
import { openVault, routerDecide } from "./vault/vault.mjs";
const vault = await openVault({ decide: routerDecide(dispatch), halted: () => "no" });
await vault.put(bytes, { label: "confidential" });   // { outcome, address }
await vault.get(address);                             // { outcome: "restore", bytes, meta } | hashonly | refuse | absent
await vault.list(); await vault.persist();
await vault.exportTo(passphrase); await vault.importFrom(file, passphrase);
```

## Tests

`test/scenario.mjs` is one scenario with 22 checks under VS-01, VS-02 and VS-03.
`test/vault-gate.mjs` runs it in Node (`cargo test -p conformance --test vault`),
and `test/vault-browser.test.mjs` runs it in headless Chromium over OPFS and the
IndexedDB fallback (`try-page.yml`). Both use the guests in `test/guests/`, the
core wasm `prismpm build` makes from the same modules with their application
record put back, each loaded only if its SHA-256 matches the pin in
`test/guests.mjs`. To rebuild one, wrap the module in its own LexLean project
with that record, run `lexlean lock && prismpm build` in the locked SDK image with
`--network none`, copy `.prism/build/<id>/core-wasm/*.wasm` here and update the pin.
